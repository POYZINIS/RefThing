# Onboarding a New Item Type

> Phase 11 shipped `image`, `video`, `audio` and `file` through the steps
> below. Use them as worked examples when adding richer types (3D models,
> web embeds, ...) without touching the core engine.

Adding a new item type is a **4-step checklist**. It needs no changes to the
core engine, schema, or sync protocol:

1. **Backend: implement `ItemTypeHandler`** in
   `backend/crates/refthing-server/src/item_types.rs` and add it to
   `HANDLERS` ahead of `FileHandler`, the catch-all. A handler provides:
   - `item_type()`: the `items.type` string.
   - `accepts(mime)`: which sniffed MIME types it takes.
   - `probe(path)`: the intrinsic size plus type metadata (for example
     `duration`), which is merged into `item_metadata`.
   - `placement(probe)`: the size the new item gets on the board.
   - `poster_job()`: the job kind that makes its poster, or `None`.
     `pyramid` is for images. `media_poster` renders a still with ffmpeg and
     runs it through `generate_poster_pyramid`, so every scaled level is a
     real WebP and never an alias of the non-image original. A new job
     registers in `lib.rs` (`jobs.register(...)`) and ends with
     `commit_ready` + `broadcast_ready`, as `jobs/media_poster.rs` does.
2. **Frontend: register a node kind.** There are four places to touch:
   - Add the kind to `NodeKind` (`canvas/nodes/types.ts`).
   - Map the item `type` to it in `itemKind` (`canvas/nodes/itemKind.ts`).
   - Add a `nodeKindRegistry` entry (`canvas/nodes/registry.ts`) with the
     renderer, texture source and capabilities.
   - Add its branch in `BoardCanvas.renderVisible`.

   Poster sources you can reuse:
   - `PyramidTextureSource.texture()`: images.
   - `PyramidTextureSource.poster()`: server posters clamped to `medium`.
     It returns null until one is resident.
   - `CardTextureSource`: filename + detail card. This is the fallback for
     any type.

   A live view is optional. It is a DOM component positioned from the
   rendered camera and mounted while the item is the lone selection (see
   `components/MediaPlayer.tsx`); a `[double_click]` binding target and a
   context-menu entry drive it. Keep the selection shell live under it:
   the element takes no pointer events, and each control sits above the
   shell and reveals on its own (`ui/useProximityReveal.ts`).
3. **Nothing else.** The canvas engine, camera, spatial index, persistence
   schema and sync protocol don't depend on item type. If you find yourself
   editing any of them to add a type, stop: the handler/renderer extension
   points are incomplete, and that is the bug to fix.
4. **Feature-flag the type if it is experimental** (`src/features.ts`). A
   disabled type degrades to a file card: it stays on the board and
   downloadable. Override the flags per machine:
   `localStorage.setItem('refthing.features', JSON.stringify({ video: false }))`.
   Unflag a type only when both its poster and live paths meet the
   performance budget (thousands of items at 60fps).

## Rendering model: poster mode and live mode

Every item type renders in one of two modes:

- **Poster mode (required).** A static texture that the canvas draws like
  any other sprite:
  - a pyramid level, generated by the backend (or, later, by the sidecar
    for Node-only tooling such as three.js GLB snapshots and puppeteer
    embed screenshots);
  - or a card painted client-side.

  You see poster mode while panning and zooming, at small sizes, and
  whenever thousands of items are on screen. It is always fast and always
  available.
- **Live mode (optional).** The rich, interactive rendering (`<video>`,
  `<audio>`, and later a 3D viewport or a live embed), entered explicitly
  by double-click or context menu. At most one item is live at a time.
  Escape, a press outside it, or a selection change leaves live mode.

The rule of thumb: **poster by default, live on demand.** The board's
60fps budget is guaranteed only because nearly every on-screen item is a
poster.

## Current types

| `type`  | Poster                                   | Live                   | Open / download |
|:--------|:-----------------------------------------|:-----------------------|:----------------|
| `image` | image pyramid (GIFs animate)             | —                      | Download        |
| `video` | ffmpeg frame → pyramid; card until ready | `<video>` over the item | Download        |
| `audio` | ffmpeg waveform → pyramid; card until ready | `<audio>` mini-player | Download        |
| `file`  | card (extension badge, name, size)       | —                      | double-click Open, Download |

The originals stream from `/blob/{hash}/full`, which honors `Range`, so
seeking works. An unrecognized file is served as `application/octet-stream`,
which means Open downloads it; HTML and SVG never render on the app origin.
